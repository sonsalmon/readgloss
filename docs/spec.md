## 변경 기록 30 (2026-11-02, 정범 요청 + 결정 "노션식 바로 변환") — 메모 쓰는 칸을 노션식 편집기로

정범 요청: 메모 쓰는 칸에서 마크다운 서식을 쓰고, 쓴 대로 그려지게. 노션처럼 `##` 다음 스페이스를 치면 그 줄이 바로 제목으로 바뀐다. 정범 결정(11-02): 쓰는 칸 자체가 바로 바뀌는 방식(쓸 땐 글·나가면 그림 방식 아님).

```
지금:  [textarea] ─ 글자 그대로 ─▶ 저장(마크다운 글) ─▶ 내보내기·학습노트
바뀜:  [Tiptap 편집기] ─ 치는 순간 제목·목록으로 그림
          └ 저장할 때 마크다운 글로 바꿈 ─▶ 저장(마크다운 글, 그대로) ─▶ 내보내기·학습노트(그대로)
       저장한 메모 줄 ─ 같은 문법으로 그림(제목·목록·굵게)
```

### 30-1. 근거 (11-02 조사)
- 동작 목록은 노션 공식 도움말(notion.com/help/keyboard-shortcuts "Markdown style")에서 가져왔다. 노션 앱 코드는 열지 않는다(약관이 역공학을 막고, 필요한 건 코드가 아니라 동작 목록).
- 편집기: Tiptap 3.32.2(MIT, ProseMirror 기반, 노션식 편집기용으로 나온 도구) + `@tiptap/markdown`(공식).
- 시험(scratchpad spike): shadow DOM 안에서 입력 규칙(`## `→제목, `- `→목록, `[] `→할 일, `1. `→번호, `**굵게**`, `---`→가로줄)이 돈다. `view.root`가 ShadowRoot로 잡히고 커서 이동도 맞다. 묶음 파일 458KB(gzip 146KB).
- 실제 메모 17건 왕복(마크다운→편집기→마크다운): `#태그`는 그대로. 달라지는 것: ① 끝 줄바꿈이 붙음(잘라서 해결) ② 글과 목록 사이에 빈 줄이 하나 생김(마크다운 뜻은 같음) ③ 평문의 `_`·`*`·`[`가 `\_`·`\*`·`\[`로 이스케이프됨(마크다운 뜻은 같음, 옵시디언에서 같게 보임) ④ 표는 사라짐(지금 표 메모 0건).
- 확인 못 함: 사람이 치는 키보드·한글 조합에서의 입력 규칙(자동 입력 도구는 키 경로를 안 탐). → T61b 끝에 정범 손 확인.

| `- `·`* `·`+ ` | 글머리 목록 |

| `[] ` | 할 일(체크칸) |

- 목록 안 Tab/Shift+Tab 들여쓰기·내어쓰기, 빈 목록 줄에서 Enter → 목록 끝. 글 블록 맨 앞 Backspace → 그 블록을 보통 글로(노션과 같음).

### 30-3. 지금 동작을 지킨다
쓰는 칸이 바뀌어도 아래는 그대로여야 한다.
- 비어 있는 칸에서 `? `/`! ` → 모드(29-2). 마크다운 글 비교가 아니라 편집기 입력 규칙으로 판정한다(저장 글은 끝 공백을 잘라 `? `가 안 남는다).
- 모드가 켜진 칸·인용이 있는 칸에서 비었거나 커서가 맨 앞일 때 Backspace → 모드 먼저, 그다음 인용(23-4·29-2). 그 다음 Backspace가 블록 되돌리기(30-2).
- ⌘Enter 저장, Esc·⌥M 접기, ⌥⇧M 지난 메모, 첫 줄 `!이름`·`?이름` 개념 명령(16-3), 15자 이상 붙여넣기 → 인용 판정(본문·튜터), 짧은 글 붙여넣기는 커서 자리.
- 쓰던 글(drafts)은 지금처럼 탭 상태에 저장. 값은 마크다운 글.
- 칸 높이: 내용 따라 늘고, 목록 높이의 절반까지(지금 textareaHeight 규칙).
- 우리 칸인지 판정(`getActiveKind`·`isPageField`·`shortcutAction`의 "입력칸 밖")이 편집기를 페이지 입력칸으로 오인하지 않는다.

### 30-4. 저장한 메모 그리기
- 메모장의 저장한 메모 줄과 패널 "다시 볼 것" 탭은 메모 글을 같은 문법(같은 Tiptap 스키마로 읽어 DOM 노드로 만든 것)으로 그린다. HTML 문자열·innerHTML은 쓰지 않는다. 링크는 http(s)만.
- `#태그` 칩(29-4)은 그대로 보인다.
- 내보내기·학습노트는 이미 마크다운이라 손대지 않는다. 단 태그 뽑기(`extractTags`)는 `\_` 같은 이스케이프를 풀고 본다.

## 변경 기록 29 (2026-11-02, 정범 요청) — 메모 표시: `?` 다시 볼 것 · `!` 깨달음 · `#태그`, 모아 보기

정범 요청: 공부하다 "나중에 찾아볼 것·이해 안 되는 것"과 "깨달은 것·기억할 것"을 메모할 때 따로 표시하고, 나중에(하루 마무리·블로그 글감) 모아 본다. 메모창에서 치는 것과 드래그해서 하는 것은 같은 메모이고, 바탕 본문(인용)이 있느냐만 다르다.

### 29-1. 생각의 틀
- 둘 다 **메모에 붙는 표시**(`mark`)다. 새 종류를 만들지 않는다. `mark`: `'question'`(❓ 다시 볼 것) | `'insight'`(💡 깨달음) | 없음.
- 모든 메모는 `#태그`를 가질 수 있다(표시가 없는 메모도).

### 29-2. 메모창에서 (정범 결정 11-02: 띄어쓰기로 구분)
- 쓰는 칸이 비어 있을 때 `?` 다음 스페이스 → `? `가 지워지고 칸이 **다시 볼 것 모드**로 바뀐다. `!` 다음 스페이스 → **깨달음 모드**. 한글 자판에서도 같은 글자(Shift+/·Shift+1).
- 모드 표시: 쓰는 칸 왼쪽 위에 칩(`❓ 다시 볼 것` / `💡 깨달음`) + 칸 테두리 색(29-4 색). 
- 칸이 비었거나 커서가 맨 앞일 때 Backspace → 먼저 모드를 끈다(인용이 있으면 그다음 Backspace가 인용을 뺀다, 23-4). Esc로 메모장을 접어도 모드는 그 칸에 남는다(인용과 같음).
- 붙여 쓰는 `?이름`·`!이름`(16-3, 용어 등록)은 그대로다. `?`·`!` 바로 뒤가 스페이스일 때만 모드다.
- ⌘Enter 저장 → 메모 `mark`에 그 모드. 저장 뒤 모드는 꺼진다.

### 29-3. 드래그해서 (본문 바탕)
- 본문 글을 고른 채(입력칸·우리 화면 밖) `?` → 드래그 + Tab(24-1)과 같다: ① 스크랩(형광펜, 표시 `question`) ② 메모장 그 소제목 칸에 인용 ③ 쓰는 칸이 다시 볼 것 모드 ④ 커서는 쓰는 칸. `!` → 같은 흐름, 표시 `insight`.
- `?`·`!`는 Shift를 누른 글자다. 판정(memo-core `shortcutAction`)은 `e.key === '?'`·`'!'`이면 Shift를 허용한다(Alt·Ctrl·⌘·한글 조합 중이면 여전히 무시). 다른 키의 Shift 무시는 그대로.
- 같은 글이 이미 스크랩돼 있으면 새로 스크랩하지 않고 그 스크랩의 표시만 바꾼다(다리 scraps `op:'mark'`).
- 형광펜 색(23-1에 더함, 배경만): 보통 스크랩 노랑 그대로, `question` `rgba(251, 113, 133, .28)`(분홍), `insight` `rgba(74, 222, 128, .28)`(초록). Highlight 이름 `readgloss-scrap-question`·`readgloss-scrap-insight`.

### 29-4. 태그
- 메모 글 안 `#글자`(앞이 줄 처음이나 공백, `#` 뒤 공백·`#` 아닌 글자 1~20자) = 태그. 구분자는 공백. 글은 그대로 저장하고, 저장 때 태그를 뽑아 `tags[]`(겹치면 하나, 앞에서부터 5개, 개념 태그 15-4와 같은 한도)에 둔다. 인용(quote) 글은 보지 않는다.
- 메모장에서 저장한 메모의 `#태그`는 작은 칩 모양으로 보인다. 저장한 메모를 고치면(edit) 태그를 다시 뽑는다.

### 29-5. 저장 (다리)
- memos `op:'save'`·`op:'edit'`: 선택 칸 `mark`(`'question'|'insight'|null`, 그 밖이면 400), `tags`(문자열 배열 ≤5, 각 1~20자, 공백·`#` 없음, 그 밖이면 400). edit에 `mark`가 없으면 그대로 둔다. GET 각 메모에 `mark`·`tags`(없으면 null·[]).
- scraps `op:'save'`: 선택 칸 `mark`(같은 값). 새 `op:'mark'`(`id`, `mark` — null이면 표시 뺌). GET 각 스크랩에 `mark`.

### 29-6. 모아 보기
- 패널 새 탭 **"다시 볼 것"**: 표시가 있는 메모를 최신순으로. 위에 거르기 칩 [전체] [❓ 다시 볼 것] [💡 깨달음] · [오늘] [7일] [전부] · 쓰인 태그 칩(`#태그 (N)`). 항목: 표시 아이콘 · 글 · 인용 첫 줄(옅게) · 태그 · 페이지 제목(누르면 그 페이지 새 탭) · 날짜. 표시 없는 메모도 태그 칩을 누르면 같이 나온다(블로그 글감용).
- 하루치 내보내기(`npm run export:day -- YYYY-MM-DD`): 그날 표시 메모가 있으면 `## 다시 볼 것·깨달음 (readgloss)` 절 — `### ❓ 다시 볼 것`, `### 💡 깨달음` 아래 `- 글 / "인용 첫 줄" — 페이지 제목`(글 안의 `#태그`는 그대로, 따로 다시 붙이지 않음). 없으면 절을 안 쓴다.
- 학습노트(`export:notes`, 16-4): 표시 메모는 `> [!help] 다시 볼 것` / `> [!tip] 깨달음` 콜아웃 첫 줄, 이어서 인용·글을 `> `로. 표시 없는 메모는 지금 모양 그대로. 태그는 글 안에 이미 있으니 따로 줄을 더하지 않는다(11-02 검증 지적: 두 번 찍힘). 앞머리 `tags`에 메모 태그도 합친다.

### 29-7. 에이전트가 정한 것 (결정 — 이유 — 틀리면 드는 비용)
- 표시는 메모 칸(mark), 새 종류 아님 — 정범 말대로 "바탕 본문이 있냐 없냐 차이"라 한 모양이 맞다, 기존 내보내기가 그대로 돈다 — 틀리면 칸 하나 옮김.
- 스크랩에도 mark를 저장 — 메모를 Esc로 버려도 형광펜 색이 남고, 다시 열 때 메모를 찾지 않아도 칠할 수 있다 — 틀리면 칸 하나 남음.
- 색 분홍·초록 — 노랑(스크랩)·하늘(단어장)과 겹치지 않음 — 틀리면 숫자만.
- 태그 1~20자·5개 — 개념 태그와 같게 — 틀리면 숫자만.
- 콜아웃 `[!help]`·`[!tip]` — `[!question] 나중에 볼 것`(용어 등록)과 섞이지 않게 — 틀리면 글자만.
- 탭 이름 "다시 볼 것" — 질문이 주 용도, 깨달음은 칩으로 — 틀리면 글자만.

### 28-1. 재생 엔진 (T53a)
- 순수 함수 `playbackStep(input)`(video-core.js, 초 단위)이 매 틱 할 일을 정한다. 입력: `t`(지금), `prevT`(직전 틱), `cues`, `cur`(지금 줄 번호, 없으면 -1), `settings`({ repeatLine, pauseEach, skipGaps }), `range`({start,end}|null, 구간 반복), `mem`({ repeatedFor, gapTo }). 출력: `{ action: 'none'|'seek'|'pause', to?, reason?, mem }`. 광고 중·멈춤 중·장면 구간(S.clip) 재생 중이면 부르지 않는다.
- 우선순위: ① 구간 반복 — range 가 있고 end > start 이며 t ≥ end → start 로 seek. ② 문장 반복(repeatLine) — 지금 줄에서 t ≥ 줄 끝 − 0.15 이고 mem.repeatedFor ≠ 그 줄 → 줄 시작으로 seek, mem.repeatedFor = 그 줄. t < 줄 끝 − 0.30 이 되면 mem.repeatedFor 를 지운다(두 번 튀지 않게). ③ 줄마다 멈춤(pauseEach) — 지금 동작(shouldPauseEach, 끝 0.08초 전) 그대로. ④ 틈 건너뛰기(skipGaps) — 지금 들어 있는 줄이 없고(줄 끝 < t < 다음 줄 시작) 다음 줄 시작 − t ≥ 0.4 이고 mem.gapTo ≠ 다음 줄 → 다음 줄 시작으로 seek. 구간 반복 중이고 다음 줄 시작 ≥ range.end 면 range.start 로.
- repeatLine 과 pauseEach 는 함께 켤 수 없다: 하나를 켜면 다른 하나를 끈다(설정에서도, 단추에서도).
- 구간 반복(Q): 첫 Q = 시작(지금 시각), 상태 줄 "구간 시작 1:02 · Q 로 끝". 둘째 Q = 끝(지금 시각) → 반복 시작, 상태 줄 "구간 1:02–1:41 · Q 해제". 끝 ≤ 시작이면 끝을 받지 않고 "끝은 시작보다 뒤여야 해요". 셋째 Q = 해제("구간 반복 해제됨"). 영상이 바뀌면 지운다. 저장하지 않는다(설정 아님).
- 설정 `video.repeatLine`(기본 false), `video.skipGaps`(기본 false). 막대 단추 [문장 반복]·[구간]·[틈 건너뛰기] 추가(지금 막대에, 세로 막대는 T53g).

### 28-8. 리스닝 드릴 + 리스닝 연습 설정 (T53e)
- L = 드릴 켜고 끄기(저장 안 함, 영상이 바뀌면 끔). 켜지면 자막 층의 두 줄을 통째로 숨기고, 화면 가운데 아래 알약 "‹ 이전 문장 A · n / 전체 · 다음 문장 D ›", 처음 한 번 안내 카드 "Space 를 누르고 있으면 자막 보기 · 두 번 빠르게 누르면 재생/정지"([가리기]로 접기).
- 드릴 중 Space: 누름(반복 키 무시) → 자막 보임, 뗌 → 숨김. 뗀 뒤 0.28초 안에 다시 누르면 재생/정지 토글(그 누름은 보이기 안 함). Space 는 유튜브로 넘기지 않는다(preventDefault·stopPropagation, 입력칸 밖·자막 층 보일 때만).
- 순수 함수 `drillSpace({ now, lastUp })` → { action:'reveal'|'toggle', nextLastUp }, 상수 DRILL_DOUBLE = 0.28.
- 리스닝 연습 모드(설정, 드릴과 따로 늘 켜 둘 수 있음): 지금 `video.hide`('off'|'hard'|'all')를 `video.hide`('off'|'word'|'line') + `video.hideTypes`({ hard:true, done:false, other:false })로 바꾼다. 옛 값 정규화: 'hard' → 'word'+hard, 'all' → 'line'. 'word' 는 고른 유형의 낱말만 가리고, 'line' 은 고른 유형 낱말이 든 줄을 통째로 가린다. done = 단어장에서 복습 끝난 낱말, other = 그 밖의 낱말. 멈추거나 자막 위에 마우스를 올리면 가린 것이 보인다.
- 설정 탭 "영상 자막" 칸: 가리기(끔·낱말·줄) + 가릴 유형 세 개 켜기.
- 막대 [가리기] 단추는 끔 → 낱말 → 줄 → 끔 으로 돈다(지금 nextHide 를 새 값으로).
- 설정 탭에서 '줄마다 멈춤'을 켤 때 '문장 반복'이 켜져 있으면 문장 반복을 끄고 줄마다 멈춤을 켠다(반대도 같다). 지금은 정규화 때문에 조용히 무시된다(1차 검증에서 찾음).

### 28-9. 칠하기 모델 (T53f)
- 다리 `/annotate` 더하기(바꾸지 않음): 요청에 `minP`(0~1, 선택)가 오면 그 값을 기준으로 쓰고(없으면 지금처럼 수준별 기준), 응답 각 항목에 `p`(모를 확률, 소수 둘째 자리)를 더한다. 영어 튜터 등 옛 호출은 그대로.
- 구간(에이전트 결정): p < 0.35 쉬움 · 0.35 ≤ p < 0.65 보통 · p ≥ 0.65 어려움. 설정 `video.wordBands`({ easy:false, medium:true, hard:true }, 랭플릭스 기본 "보통"을 readgloss 에 맞춰 보통 이상). 자막 층은 고른 구간 중 가장 낮은 경계를 minP 로 보낸다.
- 칠: 고른 구간에 든 낱말 = 주황 알약(지금 .w.hard 자리를 주황 바탕 + 흰 글자로, 대비 4.5:1 이상) · 단어장에서 복습 끝난(review.done) 낱말 = 초록 알약 · 저장했지만 아직 안 끝난 낱말 = 글자 뒤 ✓ · 알아요(known) = 칠 없음. 우선: 초록 > 주황 > ✓.
- 숙어: 저장한 구(S.phrases 의 짧은 구, 8낱말 이하)가 줄 안에 들어 있으면 그 덩어리를 한 알약으로 칠한다(복습 끝 = 초록, 아니면 주황). 설정 `video.idioms`(기본 true). 숙어 난이도 구간은 데이터가 없어 이번엔 켜기/끄기만(28-4 에 이유 기록).
- 영상 자막과 패널 대본의 칠 범위가 다른 것(패널은 학습 표현 모두)은 T53i 에서.
- 순수 함수: `bandOf(p)`, `minPFor(bands)`, `tokenColor({ p, bands, saved, done, known })`, `phraseSpans(tokens, phrases)`.
- 설정 탭: "칠하기" 줄 — 단어 쉬움·보통·어려움 세 켜기, 숙어 켜기.

### 27-1. 자막 받기 (T51a)
- 유튜브 영상 페이지(`www.youtube.com/watch`)에서만. 플레이어가 받아 오는 자막(`/api/timedtext`)을 **엿듣는다**: 새 파일 `yt-hook.js`가 페이지 쪽(MAIN world, document_start, 유튜브만)에서 XHR·fetch 응답을 보고 `window.postMessage({source:'readgloss-yt', type:'timedtext', url, body})`로 넘긴다. 확장이 자막을 따로 받지 않는다(유튜브가 자막 주소에 확인 값을 붙여서 따로 받으면 빈 응답이 오는 일이 많다). 최근 8개를 들고 있다가 `{source:'readgloss-yt', type:'replay'}`를 받으면 다시 보낸다(늦게 뜬 content script용). 4MB 넘는 응답은 버린다.
- 자막 모양: json3(플레이어 기본)·srv3·srv1(XML)·WebVTT를 읽는다. 주소의 `v`(영상)·`lang`·`tlang`(유튜브 자동 번역)·`kind=asr`(자동 생성)를 본다.
- 줄 만들기: 사람이 쓴 자막은 한 이벤트 = 한 줄(줄바꿈은 공백으로, 같은 시각 줄은 합침). 자동 생성 자막은 낱말마다 시각이 있어서 줄로 묶는다: 앞 낱말과 1.0초 넘게 벌어지면, 앞 낱말이 . ? ! 로 끝나고 3낱말 이상이면, 12낱말이나 5.5초가 차면, 쉼표 뒤 8낱말 이상이면 새 줄. 줄 끝 = 다음 줄 시작(1초 넘게 비면 마지막 낱말 + 1초).
- 고르는 자막: 이 영상의 영어 트랙(`lang`이 en, `tlang` 없음 또는 en) 중 사람이 쓴 것 > 자동 생성, 같으면 나중에 받은 것. 한국어 트랙(`tlang=ko` 또는 `lang=ko`)이 같이 있으면 한국어 줄로 쓴다(시각이 가장 많이 겹치는 줄).

### 27-2. 자막 층 (T51b)
- 플레이어(`#movie_player`) 안에 readgloss 자막(`readgloss-subs`, 닫힌 shadow)을 그리고, 그동안 유튜브 자막(`.ytp-caption-window-container`)은 숨긴다. 보이는 조건: 설정 켜짐 + 영어 줄 있음 + 유튜브 자막 단추(CC) 켜짐 + 광고 중 아님(`ad-showing`). 그래서 유튜브의 `c`가 그대로 켜고 끄기다.
- 두 줄: 영어 줄(낱말마다 누를 수 있음) + 한국어 줄(설정 "한국어 줄 보이기"). 한국어는 맥 번역(`mt`, 기기 안·무료)으로 지금 줄·앞 1줄·다음 4줄을 미리, 한 번에 하나씩 묻는다. 맥 번역이 없거나 다리가 꺼져 있으면 한국어 줄에 한 줄 안내.
- 지금 줄 = 시작이 지금 시각보다 이른 마지막 줄. 줄과 줄 사이 빈 시간에는 앞 줄을 남기되 글자만 옅게 한다(바탕은 그대로 — 밝은 화면에서도 읽히게, 27-10). 지나간 줄의 낱말도 누를 수 있다.
- 낱말 누르기 → readgloss 사전 카드(content.js `readgloss:lookup`): 문장 = 그 줄, 문맥 = 앞뒤 3줄(AI 문맥 뜻용), 출처 = 영상 주소 + 그 줄 시각(`&t=<초>s`). 그래서 카드에서 [단어장]에 넣으면 장면이 같이 남는다.
- 칠하기: 어려운 단어 = `/annotate`(지금 수준 설정·내게 맞춘 주석) 결과, 점선 밑줄 + 마우스를 올리면 짧은 뜻. 단어장 단어 = 단어장 원형의 흔한 활용형(saved-marks-core 규칙), 옅은 하늘색 바탕. 설정 "어려운 단어 칠하기"(기본 켬).
- 가리기(듣기 연습): 끔 → 어려운 단어 → 문장 전체 → 끔(H). 가린 낱말은 글자 자리만 옅은 칸(+ 밑줄)으로 남는다. 문장 전체는 낱말이 아닌 글자(한 글자 a·I, 숫자, café 등)도 가린다(27-10). 가린 낱말을 누르거나 R → 그 줄을 보인다(다음 줄은 다시 가림). 한국어 줄은 가리지 않는다(한국어 줄 설정으로 끈다).
- 줄 이동(입력칸 밖, 고른 글 없음, 조합키 없음, 한글 자판이어도 같은 자리 키): A 앞 줄 · S 이 줄 다시 · D 다음 줄 · H 가리기 바꾸기 · R 가린 줄 보기 · P 줄마다 멈춤 켜고 끄기. 줄로 옮기면 그 줄 시작으로 가서 재생한다. 유튜브 단축키(k·j·l·c·f·t·m·i·o·w 등)와 겹치지 않는다. 단 360° 영상은 유튜브가 W·A·S·D 로 둘러보기를 하니 그 플레이어(`ytp-webgl-spherical`)에서는 A·S·D 를 유튜브에 양보한다(27-10). 페이지 스크립트가 만든 키(isTrusted 아님)는 무시한다.
- 줄마다 멈춤(P): 줄 끝에서 멈춘다(한 줄에 한 번). 자막에 마우스를 올리면 잠깐 멈춤(설정, 기본 켬): 올릴 때 재생 중이었으면 멈추고, 내릴 때 사전 카드가 닫혀 있으면 다시 재생(카드가 열려 있으면 카드가 닫힐 때). 마우스는 두 줄·막대(보일 때)·풀이 위에서만 받는다(빈 자리·숨은 막대 자리·안내 위는 멈추지 않는다, 27-10). 영상 위를 눌러 카드를 닫으면 손을 뗀 뒤(유튜브의 클릭 재생·멈춤이 끝난 뒤)에 다시 재생할지 정한다.
- 자막 위 작은 막대(마우스를 올리거나 두 줄에 키보드 포커스가 있으면): [‹ A] [↻ S] [› D] [가리기: 끔/어려운 단어/문장 H] [줄마다 멈춤 P] [한] [☆ 저장] [풀이]. 모든 단추에 aria-label·키 안내, 누를 자리 24px 이상, 글자는 자막 크기를 따라 커진다(풀이·안내도). 글이 바뀌는 단추(가리기·저장)는 폭을 가장 긴 글로 고정해 눌러도 막대가 흔들리지 않는다(27-11). 막대가 숨어 있는 동안은 그 자리에 마우스가 지나가도 멈추지 않는다(visibility). 막대와 두 줄 사이는 뜻 풍선 자리(풍선이 단추를 가리지 않게).
- 키보드만 쓸 때: 두 줄 묶음이 Tab 으로 포커스를 받고(aria-label 에 키 안내), 다음 Tab 부터 막대 단추 차례(BUG-004). 두 줄에서 ←·→ = 낱말 자리 옮기기(어려운 낱말이면 뜻 풍선도, 화면 읽기 프로그램에는 낱말·뜻을 읽어 줌, 유튜브 5초 이동으로 새지 않음), Enter = 그 낱말 사전 카드(가린 낱말이면 그 줄 보이기). 낱말 자리를 옮기는 동안은 마우스를 올린 것처럼 잠깐 멈춘다. Esc = 사전 카드·확인 메시지가 떠 있으면 그것부터 닫고, 아니면 층 밖으로(유튜브 키로). 층을 나오면 낱말 자리는 지운다(다시 들어오면 첫 낱말부터, 창을 잠깐 떠난 것은 그대로). 단추를 마우스로 누른 뒤에는 포커스를 놓아 유튜브 키(k·Space)가 그대로 먹고, 키보드로 누른 뒤에는 그 자리에 둔다(막대가 사라지지 않게, 27-10). 낱말을 마우스로 눌러도 포커스는 층으로 옮기지 않는다(화살표·Space 는 유튜브 몫, 27-11). 한국어 줄은 끌어서 고를(복사할) 수 있다. 포커스 표시는 검정·흰·검정 세 겹(밝은 영상에서도 보이게).
- [☆ 저장] = 그 줄을 구·문장으로 저장: `save-phrase` { text: 그 줄, translation: 한국어 줄, kind:'sentence', url: 장면 주소, title: 영상 제목, clip: { start, end } }. 이미 있으면 ★, 누르면 빼기. 확인 메시지는 지금 쓰는 것(readglossToast)이고 자막 층 위에 띄운다(두 줄·막대를 가리지 않게, 27-10). 한국어를 맥 번역으로 받는 사이 다른 영상으로 가면 저장하지 않는다.
- [풀이] = 문맥 번역(AI, `translate-context`): text = 그 줄, before·after = 앞뒤 3줄, title = 영상 제목. 결과 칸: 번역 · 풀이(note) · 기억할 표현(☆로 저장, kind 'expression', sentence = 그 줄, url = 장면). 누를 때만 부른다(구독 한도).
- 자막 켜기 도움: 설정 "자막이 꺼져 있으면 켜기"(기본 켬)면 영상마다 한 번 CC 단추를 누른다. 5초 안에 영어 줄이 없으면 안내: CC 단추가 없음 → "이 영상은 자막이 없어요", 영어 아닌 자막만 → "영어 자막을 골라 주세요(⚙ → 자막)", 그 밖 → "자막을 기다리는 중…".
- 전체 화면: 자막 층은 플레이어 안이라 그대로 보인다. 사전 카드·확인 메시지는 전체 화면 요소 안에 붙이고(content.js) 전체 화면이 바뀌면 카드를 닫는다. 카드가 닫힐 때 `readgloss:card-closed`를 알린다.
- 글자 크기: 플레이어 높이 × 3.6% × 설정 "자막 크기"(60~160%, 기본 100), 14~44px. 한국어 줄은 0.82배.

### 27-3. 장면 저장·다리 (T51c)
- 다리 `save-phrase`에 `clip`(선택): `{ start, end }` 초, 0 ≤ start < end ≤ 86400, end − start ≤ 60, 소수 둘째 자리까지. 길이는 1/100초 정수로 잰다(소수 뺄셈 오차로 60초 구간이 거절되지 않게, 27-10). 틀리면 400. 확장은 1/100초 안의 아주 짧은 줄이면 clip 없이 보낸다. 다시 저장하면 새 요청의 clip을 쓴다(없으면 없앰 — 주소와 함께 다닌다).
- 복습 큐 카드: 낱말 카드에 `url`(있으면), 구 카드에 `url`·`clip`(있으면).
- background `words` 중계가 `clip`을 넘긴다. 새 메시지: `video-open` { url(유튜브 영상 주소), clip?: { id, start, end } } → 세션 저장소에 `pendingClip` { id, start, end, ts } 남기고 새 탭(`chrome.tabs.create`). `video-pending` { id } → 같은 영상이고 2분 안이면 `pendingClip`을 꺼내 주고 지운다(다른 영상 탭이 물으면 남겨 둔다). 영상 페이지가 뜨면 그 구간만 재생하고 끝에서 멈춘다(그 영상에 자막이 없어도 — BUG-001).

### 27-4. 복습 방식 (T51d)
- 패널 내 단어 [복습] 위에 방식 고르기: [뒤집기](지금) · [고르기] · [듣기]. 고른 방식은 설정 `reviewMode`에 남는다.
- 고르기(4지선다): 앞면은 뒤집기와 같고(낱말 + 가린 문장 / 구 영어 글) 아래 보기 4개(1~4). 정답 = 그 카드의 뜻(구는 번역 80자). 오답 3개 = 단어장의 다른 항목 뜻(같은 뜻·빈 뜻 빼고, 낱말은 낱말끼리·구는 구끼리, 모자라면 다른 쪽에서). 3개를 못 채우면 그 카드는 뒤집기로("보기를 만들 단어가 모자라서 뒤집기로 볼게요"). 고르면 바로 맞음 = 알아요, 틀림 = 아직으로 저장하고, 정답·고른 것을 색과 표시(✓ 정답 · ✕ 내 답)로 보이고 읽는 이름("정답: …"·"내 답(틀림): …")도 붙인다. 나머지 보기는 옅게. [맞았어요 · 다음]/[아직이에요 · 다음](Space·Enter). 키: 1~4 고르기, 고른 뒤 Space·Enter 다음. 새 카드에서 포커스는 보기 묶음에 둔다(Enter 를 두 번 눌러도 첫 보기가 골라지지 않게). 눌러 둔 키(반복)는 무시. 답한 뒤 방식을 바꾸면 다음 카드로(같은 카드를 두 번 답하지 않게, 27-10).
- 듣기: 앞면에 글이 없다("들은 말을 떠올려 보세요"). 소리: 장면이 있고 지금 그 영상 페이지면 그 구간(구는 clip, 낱말은 그 시각이 든 줄)을 재생, 아니면 브라우저 음성(TTS, 영어)으로 문장(낱말 카드는 저장 문장, 없으면 낱말)을 읽는다. [다시 듣기](R). Space 뒤집기 → 글·뜻, 1 아직 · 2 알아요.
- 모든 방식: 장면이 있는 카드에 [장면](재생 아이콘, 같은 영상 페이지면 그 자리 재생, 아니면 새 탭에서 그 구간 재생 — 새 탭을 여니 페이지 스크립트의 클릭은 무시), 카드에 [소리](스피커 아이콘, TTS). 아이콘은 SVG(Lucide, ISC). 장면 = 유튜브 영상 주소 + `t`(낱말) 또는 clip(구). 구간 재생 중 사용자가 끝 너머로 옮기면 그 자리에서 멈추지 않고 구간만 끝낸다.

### 27-5. 패널 [영상] 탭 (T51e)
- 유튜브에서만 탭이 보인다(영상 페이지가 아니면 "유튜브 영상 페이지에서 보여요").
- 머리: 영상 제목 · "영어 자막 · N줄 · 자동 생성/사람이 씀".
- 어려운 단어 미리 보기: [어려운 단어 보기] → 대본 전체 낱말을 300개씩 `/annotate`에 물어 `낱말 · 뜻 · ×횟수` 칩(처음 나온 순, 60개까지). 누르면 처음 나온 줄로 간다.
- 대본: 줄마다 `시각 · 영어`(+ 받아 둔 한국어). 지금 줄 강조·따라 스크롤(사용자가 3초 안에 스크롤했으면 안 따라감). 줄 누르기 = 그 줄로 가서 재생. 줄마다 [☆]. [한국어 모두 보기] = 지금 줄부터 차례로 맥 번역(다시 누르면 멈춤, 단추 글에 "한국어 받는 중 N/M · 멈추기"). 한국어 줄 설정을 꺼 두어도 대본 전체를 받는다(27-10). 지금 줄 근처 미리 번역은 자막 층이 보이고 한국어 줄이 켜졌을 때만.
- [영상] 탭은 탭 줄 맨 앞(유튜브에서 패널을 열면 바로 보인다). 탭이 6개가 되므로 탭 이름은 한 줄로 두고, 넘치면 탭 줄을 옆으로 넘긴다(BUG-002, 모든 사이트 공통).

### 27-6. 설정 (T51f)
- `video`: { subs: true(유튜브 자막 층 켜기), ko: true(한국어 줄), hard: true(어려운 단어 칠하기), hoverPause: true, autoCC: true, fontPct: 100(60~160, 10씩), hide: 'off'|'hard'|'all', pauseEach: false }. `reviewMode`: 'flip'|'choice'|'listen'.
- 설정 탭에 "영상 자막" 칸: 위 켜기 5개 + 줄마다 멈춤 + 가리기(끔·어려운 단어·문장 전체) + 자막 크기.

### 27-7. 에이전트가 정한 것 (결정 — 이유 — 틀리면 드는 비용)
- 자막은 엿듣기만 — 확장이 따로 받으면 확인 값 때문에 빈 응답이 잦다 — 플레이어가 자막을 안 받으면(자막 꺼짐) 우리도 없다, 그래서 CC 켜기 도움을 둔다.
- 유튜브 CC 단추가 켜고 끄기 — 손에 익은 `c` 하나 — 단추 모양이 바뀌면 늘 켜진 것으로 본다.
- 한국어 줄은 맥 번역 — 무료·빠름·한도 없음 — 자막 조각이라 어색할 수 있다, 그때 [풀이](AI)로.
- 줄 키 A·S·D·H·R·P — 유튜브가 안 쓰는 글자, 왼손 자리 — 다른 확장과 겹치면 글자만 바꾼다.

- 표 안을 드래그(몇 줄만 걸쳐도 됨)한 채 Tab(또는 ⌥M) → 지금처럼 스크랩 + 메모장 인용인데, 인용이 줄글이 아니라 **표**: 걸친 줄 + 머리줄(thead 또는 첫 줄이 모두 th면 그 줄). 고른 범위가 표 밖까지 넘으면 지금처럼 줄글.
- 칸 글: 공백 정리, 칸 안 `code`·`kbd`·`samp`는 백틱으로 감쌈. 상한 8칸·30줄·칸 300자, 넘으면 자르고 "표가 커서 30줄까지만 담았어요".
- 인용 data `quote.table = { head: string[] | null, rows: string[][] }`. exact는 지금처럼(스크랩·위치용 줄글), table이 있으면 exact 상한 4000.
- 메모장(쓰는 중 인용·저장된 메모): 작은 표(가로 스크롤), 백틱 부분은 고정폭. 학습노트: 마크다운 표(`|` → `\|`, 머리줄 없으면 첫 줄을 머리줄로), 원문 링크는 표 아래 줄 `[↗](…)`, 빈 줄 뒤 메모 글.
- C(코드 인용)·형광펜 카드 인용은 표로 바꾸지 않는다.

### 25-4. 에이전트가 정한 것
- 한 글자 단축키는 "고른 글이 있고 입력칸 밖"일 때만 — 평소 타이핑에 영향 없음 — 페이지가 같은 키를 쓰면 고른 상태에서만 겹침.
- 코드 인라인 기준 120자·줄바꿈 없음 — 흔한 한 줄 명령 — 틀리면 숫자만.
- 표는 새 단축키 없이 Tab이 표 안이면 저절로 — 손에 익은 동작 하나 — 줄글로 원하면 표 밖까지 고르면 됨.

### 20-1. 모를 확률 p(원형)
- 출발점(등급표): A1 .02, A2 .05, B1 .15, B2 .35, C1 .60, C2 .75, 목록 밖 .72(지금처럼 어느 수준에서도 붙게).

- 주석은 p ≥ 기준일 때 붙는다. 기준 = 설정 "수준"(A2~C2)이 정하는 바탕 값(A2 .04, B1 .10, B2 .30, C1 .50, C2 .70) + 자동 조절 값.

## 변경 기록 18 (2026-10-15, 정범 결정) — 자동 주석을 겹쳐 그리기로: 페이지 글자를 건드리지 않는다

### 18-1. 문제
- HTB Academy(웹앱)에서 "저장하고 다음"을 누르면 "실패"가 뜨고, 새로 고치면 다음 섹션이 열린다. 주석을 끄면 안 뜬다.
- 원인: 자동 주석이 페이지의 글자 노드를 빼고 `<ruby>` 조각으로 갈아 끼운다(`annotate-core.js` `annotateBlock`의 `node.replaceWith`). 웹앱(React·Vue 등)은 자기가 만든 글자 노드를 기억해 고치거나 지우는데, 그 노드가 빠져 있어 화면 갱신이 오류로 끝난다.

### 18-2. 바꾸는 방식(모든 사이트)
- 페이지 DOM(글자·요소)을 바꾸지 않는다. 주석 단어는 `Range`로만 가리킨다.
- 단어 표시(mark: 색·밑줄·배경)는 CSS Custom Highlight API(`CSS.highlights`, 이름 `readgloss-ann`).
- 뜻 글자는 우리 겹침 층 하나(`readgloss-ann-layer`, shadow host, `pointer-events:none`, 맨 위)에 단어마다 작은 글자로 그린다. 위치는 단어 바로 위 가운데(`position: fixed`, 단어 `getClientRects()[0]` 기준).
- 다시 그리기: 스크롤(문서·안쪽 스크롤 칸 모두, capture), 창 크기, 주석 블록 크기 변화, 페이지 글자 변화 때 한 프레임에 한 번(rAF). 화면 근처 블록만 계산한다.
- 단어가 다른 것에 가려졌거나(고정 머리말·창) 스크롤 칸 밖이면 뜻 글자를 숨긴다(단어 가운데 `elementFromPoint`가 그 단어의 부모 요소 안이 아니면 숨김).
- 페이지가 그 글자를 바꾸거나 지우면(노드가 끊기거나 글이 달라지면) 그 단어 주석을 버리고 블록을 다시 처리한다.
- 뜻 글자 크기·색·투명도·굵기는 지금 설정 그대로(크기는 단어 글꼴 크기 × 설정 %, 색 "글자색"은 단어 요소의 계산된 색).
- 설정 "오른쪽 (뜻)"은 자리를 만들 수 없어 "위"로 그린다. 패널 설정의 위치 선택에서 "오른쪽"을 뺀다(저장값 right는 top으로 읽음).
- "뜻 글자 복사 허용"(allowCopy)은 뜻 글자가 본문이 아니므로 의미가 없어져 설정에서 뺀다(저장값은 무시).

### 18-3. 에이전트가 정한 것 (결정 — 이유 — 틀리면 드는 비용)
- position:fixed + 스크롤마다 rAF 다시 계산 — 안쪽 스크롤 칸(웹앱에 흔함)도 따라감 — 단어가 많은 페이지에서 스크롤이 무거우면 화면 근처만 계산하는 범위를 줄인다.

- `export:concepts`의 개념 문서 앞머리: `type: concept`, `title`, `description`(정의 첫 항목, 없으면 "(아직 설명 없음)"), `aliases`, `tags`, `sources`(학습노트 경로들), `created`, `updated`.
- 본문: `# <이름>`, 첫 줄 = description 한 문장, 정의 목록, `## 나온 곳`(`- [[notes/<할일>/<페이지>]] — <소제목>`), `## 관련 페이지`(`- [[<관련 개념>]] — 관련`).
- llm-wiki로 보내기(정범 결정 10-15): 세션 끝에 에이전트가 "석 달 뒤에도 찾을 것" 후보 개념을 보여 주고, 정범이 고른 것만 `~/dev/llm-wiki/raw/sources/YYYY-MM-DD-<slug>.md`(llm-wiki 스킬 원자료 형식)로 넣는다. 자동으로 보내지 않는다(원자료는 정리 때 OpenAI로 간다).

### 16-6. 화면 설정
- 투명도 두 가지(패널 설정 탭): "입력 칸"(메모장 쓰는 칸·개념 칸 입력) 40~100%, "나머지"(메모장 틀·카드·패널) 40~100%. 기본 100%. 마우스를 올리거나 입력 중이면 100%로 잠깐 진하게.
- 투명도 자동(설정 "읽는 동안 흐리게", 기본 켬): 두 상태를 둔다.
  - 읽는 중(흐림): 위 두 투명도 값을 쓴다.
  - 메모 중(진함, 100%): 메모장을 열 때, 쓰는 칸에 칠 때, 메모장 위에 마우스가 있을 때.
  - 메모 중 → 읽는 중: 마우스가 메모장 밖으로 나가고 쓰는 칸에서 1.5초 동안 치지 않았을 때, 또는 본문을 한 번 누를 때.
- 쓰는 칸이 기본 포커스(메모장이 열려 있을 때): 본문을 누르거나 드래그하거나 카드(뜻·드래그)·스크랩을 쓴 뒤, 그 일이 끝나면 커서를 지금 소제목 칸의 쓰는 칸으로 돌려놓는다. 그래서 메모장을 누르지 않고 바로 친다.
  - "끝"의 뜻: 선택이 비어 있고(드래그 선택이 남아 있으면 기다림), 우리 카드가 닫혀 있고, 마지막 마우스 동작 뒤 0.3초가 지났다.
  - 돌려놓지 않는 때: 페이지 입력칸·편집 영역에 커서가 있을 때, 우리 다른 칸(개념 칸·확인 메시지 메모·패널 입력)에 커서가 있을 때, 메모장이 접혀 있을 때.
  - 포커스를 옮길 때 페이지·메모장 스크롤은 움직이지 않는다(`focus({preventScroll:true})`).
  - 커서가 쓰는 칸에 있어도 ⌥S·⌥M·⌥⇧M·Esc 같은 기존 단축키는 그대로 동작한다.
- 공부 모드(퀵 메뉴 [공부 모드], 단축키 없음): 이 창을 전체 화면으로 바꾸고(`chrome.windows.update(windowId, {state:'fullscreen'})`, background에서) 메모장을 붙인 모양으로 연다. 다시 누르면 원래 창 상태로. 전체 화면에서 주소창·북마크바가 숨는지는 브라우저 설정("전체 화면에서 도구 모음 항상 표시" 끔)에 달렸다 — 확장이 주소창·북마크바만 따로 숨길 수는 없다(브라우저가 막음).
- 메모장 붙이기: 메모장 위 줄에 [붙이기] 버튼. 누르면 메모장이 화면 오른쪽에 붙고, 페이지 본문이 그만큼 왼쪽으로 줄어든다(`html` 오른쪽 여백). 경계를 끌어 폭을 바꾼다(260~50%). 다시 누르면 떠 있는 모양으로. 붙인 상태·폭은 기억한다. 고정 머리말이 겹치는 사이트는 떠 있는 모양을 쓴다.

## 변경 기록 15 (2026-10-15, 정범 요청·승인) — 내 개념 v2: 목록 편집기·다시 열기·자동 저장·태그

### 15-1. 설명 칸 = 마크다운 목록 편집기
- 개념 설명 칸(개념 칸 `openForm`, 패널 개념 상세)은 마크다운 순서 없는 목록으로 쓴다. 빈 칸이면 `- `로 시작한다.
- Enter: 다음 줄에 같은 들여쓰기의 `- `를 만든다. 지금 항목이 `- `만 있고 비었으면 그 항목을 지우고 한 단계 내어쓴다(맨 바깥이면 그대로).
- Shift+Enter: 그 항목 안 줄바꿈(다음 줄을 항목 글 시작 위치까지 공백으로 맞춘다).
- Tab: 지금 줄을 2칸 들여쓴다. Shift+Tab: 2칸 내어쓴다. 포커스가 칸 밖으로 나가지 않는다.
- 저장은 쓴 마크다운 그대로. 저장할 때 내용 없는 `- ` 줄은 뺀다. 상한 500자는 그대로.
- 한글 조합 중(`isComposing`)에는 위 키를 처리하지 않는다.

### 15-2. 방금 저장한 것 다시 열기

- 마지막 저장이 없으면 아무것도 안 한다.

### 15-3. 회색·점선 표시를 누르면
- 패널 개념 상세가 열리고 설명 칸에 포커스. 설명 끝에 새 `- ` 줄을 만들고 그 뒤에 커서(이미 끝이 빈 `- `면 그 뒤).

- Esc: 상세를 닫는다(대기 중 저장은 즉시 보낸다). ⌘Enter: 즉시 저장하고 패널을 접는다.

## 변경 기록 14 (2026-10-13, 정범 요청·승인) — 메모장 v2

### 14-2. 화면 — 이 페이지 문서
- 메모장은 이 페이지의 소제목(h1~h3) 순서대로 칸을 보인다. 칸마다: 소제목 글, 그 아래 이 소제목에 저장된 메모(오래된 것 먼저, 인용이 있으면 노란 인용 줄), 맨 끝 쓰는 칸.
- 소제목이 없는 페이지는 칸 하나(페이지 제목).
- 저장한 메모를 누르면 그 소제목 위치(인용이 있으면 인용 자리)로 본문을 스크롤하고 깜빡인다. 메모마다 [지우기].
- 맨 위 줄: `<할 일 제목> › <페이지 제목>`. 이 줄을 끌어 메모장을 옮긴다. 오른쪽 아래 모서리를 끌어 크기를 바꾼다(가로 260~640px, 세로 200~화면 높이-40px).
- 위치·크기는 기억한다(`chrome.storage.local`, 모든 페이지 공통). 화면이 작아져 밖으로 나가면 창 전체가 화면 안에 들어오게 당긴다(크기를 먼저 화면에 맞게 줄인다).
- ⌥M으로 열거나 칸을 다시 그리면 지금 칸 쓰는 칸에 커서를 둔다. 단, 페이지의 입력칸에 커서가 있으면 옮기지 않는다. ⌘Enter·Esc는 메모장 어디에 커서가 있어도 먹는다.

### 14-3. 스크롤 따라가기
- 지금 소제목 = 화면 위 1/3 선보다 위에 있는 마지막 소제목(12-3과 같은 규칙). 스크롤할 때마다 다시 정한다(100ms마다 한 번까지).
- 지금 소제목이 바뀌면 메모장이 그 칸을 보이게 스크롤하고 그 칸 쓰는 칸에 커서를 둔다. 커서는 쓰는 칸 글의 끝이다. 줄을 더하지 않는다.
- 쓰는 칸에 마지막으로 친 지 1.5초가 안 됐으면 커서를 옮기지 않는다(메모장 화면 스크롤만 따라감).
- 쓰던 글과 인용은 소제목마다 따로 남는다(탭별 상태, 12-7의 session 저장에 소제목 key별로).

### 14-4. 인용
- 인용 = `{exact(≤1000), prefix, suffix}`(스크랩과 같은 방식, 글 고를 때 색인에서 뽑음) + 고른 글이 든 소제목.

- 저장하면 메모 data에 `quote`로 들어간다. 메모의 `headings`는 그 소제목까지의 사슬.

### 14-5. 에이전트가 정한 것 (결정 — 이유 — 틀리면 드는 비용)
- 저장 단위는 메모 하나 = 생각 하나, 화면은 소제목 문서 — 정범 승인. 개념·튜터·세션 정리에 잇기 쉽다 — 소제목마다 긴 글이 필요해지면 "칸 = 글 하나" 방식으로 바꾼다.

- 옛 `selection` 칸은 남긴다(읽기만). 새 메모는 `quote`를 쓴다.

3. 페이지 표시: 설명 없는 개념은 점선 밑줄(Highlight 이름 `readgloss-later`, `text-decoration: underline dotted rgba(136,135,128,0.7)`). 설명 있는 개념은 지금처럼 회색.
4. 마우스 카드(설명 없음): "나중에 볼 것 · 아직 설명 없음" · 본 곳(제목) · [지금 쓰기]. [지금 쓰기] → 기존 [내 개념으로] 칸을 그 개념 고치기로 연다.
5. 설명을 채워 저장하면 바로 내 개념 표시(회색)로 바뀐다.
6. 개념 탭: 위에 거르기 칩 [전체 · 내 개념 · 나중에 볼 것(N)]. 나중에 볼 것은 저장한 순서(오래된 것 먼저). 상세에 "본 곳" 줄과 설명 칸.

### 13-2. 데이터
- 개념 save의 `definition`은 0~500자(빈 글 허용). 개념 data에 `seen {url, title, sentence}`(선택, sentence ≤300자)를 더한다.
- `/concepts` GET의 각 개념에 `later: definition === ''`.
- export:concepts: 나중에 볼 것도 `<이름>.md`로 만들되 정의 자리에 `(아직 설명 없음)`과 본 곳 링크를 쓴다. `concepts/나중에-볼-것.md` 목록 한 장(오래된 것 먼저, 이름 · 본 곳 · 날짜).
- export:pending: 날마다 `나중에 볼 것 N개` 한 줄(그날 새로 넣은 것).

### 13-3. 공부와 잇기
- 학습 세션을 끝낼 때 에이전트가 나중에 볼 것 개수를 말하고, 지금 할 일과 가장 가까운 것 하나를 고른다(HANDOFF 3절에 한 줄).
- Aside 튜터 스킬 `tutor-here`: 신호어 `나중에 볼 것` → 설명 없는 개념 목록에서 하나(이 페이지·할 일과 가까운 것) 골라 3-4 배경 설명 방식으로 설명한다.

### 13-4. 에이전트가 정한 것
- 나중에 볼 것도 같은 개념 점(kind `concept`) — 설명을 채우면 따로 옮길 것이 없다 — 나중에 볼 것만 따로 다뤄야 하면 `later` 값으로 거른다.
- [나중에]는 칸을 띄우지 않는다 — 흐름을 끊지 않는 것이 목적이다 — 이름이 틀렸으면 개념 탭에서 지우고 다시 넣는다(개념 탭 상세에는 이름 칸이 없다).

### 11-1. 화면 흐름

1. **[내 개념으로].** 드래그 카드·사전 카드·스크랩북 스크랩마다 버튼. 누르면 작은 칸: 개념 이름(기본 = 고른 글자, 1~80자), 별칭(쉼표로 0~5개, 각 ≤80자), 내 정의(1~500자, 줄바꿈 허용), 관련 개념(이름 입력 → 있는 개념 자동완성, 0~10개). [저장]하면 바로 그 페이지에 표시된다. 지금 할 일(변경 기록 10-3 짐작 결과)과, 같은 카드에서 고른 문장이 스크랩돼 있으면 그 스크랩에 자동으로 잇는다. 같은 이름 개념이 이미 있으면 새로 만들지 않고 그 개념을 열어 고치게 한다.

3. **마우스 올리기(0.3초).** 작은 카드: 개념 이름 · 내 정의 · 관련 개념 칩 · "처음 나온 곳: <할 일 제목> · <페이지 제목>". 카드 밖으로 나가면 닫힌다.

### 10-1. 화면 흐름

1. **드래그 카드 [스크랩].** 두 단어 이상 드래그 카드의 버튼 줄에서 [단어장] 다음에 [스크랩]. 카드가 열려 있을 때만 ⌥S(Option+S)도 같은 동작. 누르면: 저장 → 그 문장에 형광펜 → 저장 확인 메시지 "스크랩했어요" + [메모](변경 기록 9의 `readglossToast` 그대로) → 선택 해제·카드 닫기([단어장] 저장과 같음). 같은 페이지의 같은 문장이 이미 스크랩돼 있으면 버튼이 [스크랩됨]이고 누르면 뺀다(형광펜도 걷는다). AI는 쓰지 않는다.
2. **할 일 줄.** 카드 맨 아래 한 줄: `→ <할 일 card_title> › <페이지 제목> › <가장 가까운 소제목>`. 할 일 이름을 누르면 목록(오늘 쓴 할 일들 · 다음 한 걸음 할 일 · 이 주소에 맞는 할 일들 · 인박스)이 뜨고, 고르면 이번 스크랩에 쓰인다.
3. **할 일 짐작**(10-3 규칙). 커리큘럼 밖 페이지면 [스크랩]을 누를 때 카드 안에 "지금 하는 '<할 일>'에 넣을까요? [넣기] [인박스]". 답은 그 페이지(정규화 주소)에 그날(서울 날짜) 동안 기억해서 다시 묻지 않는다. 후보 할 일이 없으면 묻지 않고 인박스.
4. **형광펜.** 옅은 노랑. 페이지 글은 바꾸지 않는다(10-6). 페이지를 열 때 그 주소의 스크랩을 다리에서 받아 다시 칠한다. 늦게 그려지는 페이지는 글이 바뀔 때마다 10초까지 다시 찾는다. 못 찾은 스크랩은 스크랩북에 "페이지에서 못 찾음"으로 보인다.
5. **스크랩북 탭**(패널, 순서 22 — 내 단어 20과 공부 기록 25 사이). 할 일(카드 제목 · 개수) → 페이지(제목. 같은 할 일 안의 다른 페이지 주소 아래 경로면 들여쓴다) → 소제목 → 문장(형광 표시) · 번역 · 메모. 맨 아래 인박스. 스크랩마다 [할 일 바꾸기] [메모] [지우기].
6. **그 문장으로 이동.** 스크랩북에서 문장을 누르면 같은 페이지면 그 자리로 스크롤, 다른 페이지면 지금 탭에서 그 주소를 열고 찾은 뒤 스크롤. 잠깐 진하게 깜빡여 어디인지 보여 준다.
7. **넘김 막대.** 6번으로 이동하면 화면 아래 가운데에 `스크랩 n / N  ←  →  ✕`. 같은 할 일의 스크랩을 저장 순서로 넘긴다(다른 페이지면 그 페이지를 연다). 막대가 떠 있고 입력창 밖이면 키보드 ← → 도 된다. ✕로 닫는다. 떠 있는 버튼 퀵 메뉴의 [스크랩 보기]는 이 페이지에 스크랩이 있을 때 첫 스크랩부터 막대를 연다.
8. **메모.** 저장 확인 메시지의 [메모]나 스크랩북 [메모] → 그 스크랩의 `memo`(0~1000자, 변경 기록 9와 같은 규칙).
9. **공부 기록.** 스크랩 1건 = `study-log.jsonl`에 `kind:'scrap'` 한 줄. 공부 기록 탭 종류에 "스크랩".

### 10-2. 데이터 — `data/scraps.json`(새 파일)

```json
{ "v": 1, "scraps": { "<id>": {
  "id": "정규화 주소 + exact + prefix 의 sha1 앞 12자",
  "task": "S1-04",
  "url": "https://portswigger.net/web-security/access-control",
  "title": "페이지 제목",
  "headings": ["가장 가까운 h1", "h2", "h3"],
  "quote": { "exact": "스크랩한 문장", "prefix": "앞 32자", "suffix": "뒤 32자" },
  "pos": 1234,
  "translation": "카드에 나온 번역(문맥 번역이 있으면 그것)",
  "memo": "",
  "ts": 1791443403464
}}}
```

- `task`는 `^(?:S\d-\d{2}[a-z]?|BUF-\d{2})$` 또는 `null`(= 인박스). `exact` 1~1000자, `prefix`·`suffix` 각 ≤64자, `headings` ≤3개 × ≤200자, `title` ≤300자, `translation` ≤2000자, `memo` ≤1000자. 넘으면 400.
- 주소 정규화: `#` 뒤를 버리고, `utm_*` 쿼리만 지우고, 끝 `/`를 뗀다. 나머지 쿼리는 남긴다.
- 다리 `/scraps`(토큰 필요, 다른 주소와 같은 방식):
  - `GET /scraps` → `{scraps:[...], tasks:{id: card_title}}`(스크랩북용, `tasks`는 스크랩에 나온 할 일만). `GET /scraps?url=<주소>` → 그 페이지 스크랩만.
  - `POST /scraps` op `save`(새로 또는 같은 id면 덮되 `memo`·`ts` 유지) · `remove {id}` · `memo {id, memo}` · `move {id, task|null}` · `guess {url}` → `{task, ask, candidates:[{id, title}], matches:[...]}`(10-3).
  - 저장은 `words.json`과 같은 방식(쓰기 큐 + 임시 파일 뒤 이름 바꾸기).

### 10-4. 학습 폴더로 옮기기 — 밀린 날 따라잡기

- `npm run -s export:pending` — `data/export-state.json`의 `lastDay`(처음 값 `2026-10-06`) 다음 날부터 오늘까지, 저장 기록이 있는 날마다 `### YYYY-MM-DD` + 기존 `export:day`와 같은 "## 영어 표현 (readgloss)" 마크다운, 그 날 스크랩 개수와 할 일별 문서 이름 한 줄을 출력한다. 다리 없이 `data/`를 읽기만 한다.
- `npm run -s export:scraps -- --to <폴더>` — `scraps.json` 전체로 `<폴더>/<할일id>.md`(할 일 문서: 페이지 목록, 하위 페이지 들여쓰기, 페이지 문서 링크)와 `<폴더>/<할일id>/<페이지 이름>.md`(소제목을 `##`·`###`로, 그 아래 `>` 인용 문장 · 번역 · 메모 · 원문 주소)를 다시 만든다. 인박스는 `<폴더>/inbox.md`. 파일 머리에 "자동 생성 — 고치려면 확장 스크랩북에서". 내용이 같으면 파일을 다시 쓰지 않는다(커밋 잡음 방지). 스크랩이 사라진 할 일의 문서는 지운다.
- `npm run -s export:mark -- YYYY-MM-DD` — 에이전트가 학습 폴더에 붙이고 커밋한 뒤 `lastDay`를 그 날로.
- `npm run -s scraps -- move <id> <할일id|inbox>` — 다리 `/scraps` `move`를 토큰으로 부르는 작은 명령(인박스 분류를 정범이 승인한 뒤 에이전트가 쓴다).
- **학습 세션 절차(에이전트):** 세션을 열 때와 끝낼 때 `export:pending`을 보고, 밀린 날마다 그날 `learning-records/YYYY-MM-DD.md`에 "영어 표현" 절과 "스크랩 N개 → `scraps/<할일>.md`" 한 줄을 붙이고(파일이 없으면 만든다), `export:scraps -- --to ~/dev/learning/security-career/scraps`로 문서를 다시 만들고, 커밋한 뒤 `export:mark`. 마무리 때 인박스가 있으면 할 일 배정안을 내고 정범이 받으면 `scraps move`. 이 절차를 학습 폴더 `HANDOFF.md` 3절에 적고 메모리 `readgloss-to-learning-records`를 고친다.
- 작업실 설계서 29절 — 학습노트는 인용 원문까지 비공개 작업실 서버에 올린다(10-20 사용자 결정, 변경 기록 26). 학습 저장소는 원격 없이 둔다.

### 10-6. 에이전트가 정한 것 (결정 — 이유 — 틀리면 드는 비용)

- 직접 만들고 부품은 `approx-string-match`(MIT, 의존성 없음, 마지막 배포 2.0.0 2022-04 — 작고 다 만든 부품이라 파일로 복사해 둔다, 10-08 `npm view`로 확인)만 가져온다(라이선스 고지 포함). 다시 찾기는 Hypothesis 방식(정확 일치 → 근사 일치 → 앞뒤 문맥·위치 점수로 후보 고르기) — 조사(`docs/research/2026-10-08-scrap-tools-survey.md`) 결과 로컬 전용·소제목 아래·← → 를 다 하는 기존 도구가 없다 — 틀리면 부품 교체 한 번.
- 형광펜은 CSS Custom Highlight API(`CSS.highlights`, `::highlight()`) — 페이지 글을 바꾸지 않아 다른 기능(주석·문단 번역)과 안 부딪힌다. Aside는 Chromium 153(105부터 지원)이다 — **확장 격리 환경에서 되는지는 확인 안 했다.** T24 첫 단계에서 시험하고, 안 되면 `<mark data-readgloss>`로 감싸는 방식으로 바꾼다(그때는 주석·문단 번역과 겹치는지 시험 추가).
- 이동은 주소를 연 뒤 확장이 문장을 찾아 스크롤한다. 글 조각 주소(`#:~:text=`)는 쓰지 않는다 — 클릭하면 형광펜이 사라지고, 찾았는지 확장이 알 수 없고, 늦게 그려지는 페이지에서 불확실하다(`docs/research/2026-10-08-text-fragments.md`) — 틀리면 저장 때 조각 주소를 보조로 더한다.
- 스크랩은 `words.json` 구·문장(`phrases`)이 아니라 새 파일 — `phrases` 번호는 문장 글자로만 매겨서 다른 페이지의 같은 문장이 겹친다 — 틀리면 합치는 이전 한 번.
- ⌥S는 카드가 열려 있을 때만(전역 단축키 `commands` 안 씀) — 입력창에서 ⌥S가 ß를 치는 것과 안 부딪히고 manifest 권한이 안 는다 — 카드 없이도 원하면 그때 `commands` 추가.
- 소제목은 h1~h3, 앞뒤 문맥은 32자(Hypothesis 기본) — 기존 `headingsAbove`(`extension/selection.js`)를 다시 쓴다 — 짧으면 숫자 하나.
- 할 일 짐작은 다리가 한다(확장은 결과만 받음) — `roadmap.json`·`NOTES.md`가 맥 파일이라 — 학습 폴더 위치가 바뀌면 설정값 하나.
- 관계는 이번에 스크랩의 `task`·`url`·`headings` 칸뿐이다. 단어↔개념↔할 일의 일반 관계(점과 선)는 다음 조각 "내 개념"에서 설계한다 — 지금 만들면 쓰지 않는 구조가 생긴다 — 그때 `scraps.json`을 점으로 옮기는 이전이 한 번 든다.

# 영어 기술 문서 읽기 도우미 (브라우저 확장) 명세 초안

용어 3개만 먼저 풀어 둡니다.
- **다리(bridge)**: 확장은 브라우저 안에 갇혀 있어서 `claude` 명령을 직접 못 돌립니다. 내 맥에서 확장 대신 `claude`를 실행하고 결과를 돌려주는 작은 프로그램입니다.
- **캐시**: 한 번 받은 답을 저장해 두는 곳입니다. 같은 단어를 다시 물으면 AI를 부르지 않고 저장본을 씁니다.
- **ruby**: 글자 위에 작은 글씨를 얹는 HTML 태그입니다(일본어 후리가나 방식). Relingo식 "단어 위 작은 한국어 뜻"이 이것입니다. 조사 결과 Relingo가 정확히 이 모양인지는 문서로 확인하지 못했습니다. 이 명세는 사용자가 말한 모양을 기준으로 합니다.

## 1. 한 줄 목표

영어 보안 문서를 웹에서 읽다가, 모르는 단어는 더블클릭으로 한국어 뜻을 보고, 어려운 단어는 위에 작은 한국어 뜻이 자동으로 붙고, 문단은 한 번에 번역해서 보는 개인용 확장을 만듭니다. 번역은 API 키 없이 내 `claude` 구독으로 합니다.

## 2. 핵심 기능 3개

시간 기준은 직접 잰 값에서 가져왔습니다(2026-10-06, claude 2.1.283, haiku).
- 상주 `claude` 단어 1개: 2.9~4.0초(같은 프로세스 두 번째 호출부터)
- 상주 `claude` 문단(101단어): 2.9~5.4초
- 상주 `claude` 20단어 일괄: 1.9~4.8초
- `claude` 콜드 스타트(프로세스를 새로 띄워 단어 1개): 약 8초
- **주의: 생각(thinking) 기능을 끄지 않으면 새 프로세스의 첫 일괄 요청이 56~80초 걸렸습니다.** AI가 생각 토큰을 약 7,100개 쓰기 때문입니다. `--settings '{"alwaysThinkingEnabled":false}'`를 붙이면 같은 첫 요청이 3.7초(출력 217토큰)로 줄었습니다. `--effort low`만으로는 70.8초 그대로였습니다. 그래서 다리는 생각 끄기 설정을 반드시 붙입니다(7절 3번).

| # | 사용자가 보는 동작 | 성공 판정 |
|---|---|---|
| 1 | 영어 단어를 더블클릭하면 그 옆에 작은 말풍선으로 한국어 뜻이 뜹니다. | 캐시에 있는 단어는 0.3초 안에 뜹니다. 없는 단어는 0.3초 안에 "가져오는 중…"이 뜨고, 뜻은 6초 안에 나옵니다. 한 번 본 단어를 다시 누르면 AI 호출이 0번입니다. |

## 3. 안 할 것 / 나중에 할 것

**안 할 것**
- 영상·자막 번역.
- 단어장 동기화 서버. 나중에 단어장이 필요해지면 다리 쪽 파일 하나로 둡니다.
- 크롬 웹 스토어 게시, 남에게 배포. 약관상 개인용일 때만 안전하다는 해석이 자연스럽습니다(10절).
- 페이지 전체를 한꺼번에 이중언어로 바꾸는 기능. 문단 단위만 합니다.
- API 키(과금) 연동. CLI 로그인 토큰을 꺼내 쓰는 방식도 안 합니다. 공식 `claude` 프로그램만 실행합니다.
- codex·agy 연동은 첫 버전에서 안 합니다.

**나중에 할 것**
- PDF·EPUB: 확장 안에 자체 뷰어 페이지를 붙여서, 그 페이지에도 같은 3기능을 올립니다. relyless가 확장 안에 PDF.js 뷰어를 넣은 방식(`extension/pdf-viewer.*`, MPL-2.0)을 참고합니다.
- "알아요" 버튼: 쉬운 단어가 반복해서 주석에 붙으면 도입합니다.
- 오프라인 사전(kaikki에서 추린 영한 JSON): 캐시에 없는 단어를 기다리는 게 거슬리면 도입합니다.
- 다리에 OpenAI 호환 주소(`/v1/chat/completions`)를 하나 더 열어 기성 확장(Kiss Translator 등)도 붙일 수 있게 하는 것.
- codex 둘째 엔진. 같은 다리 안에서 엔진만 바꿉니다.

## 4. 모양 비교

- **A**: 기성 오픈소스 확장(Kiss Translator 또는 Read Frog)에 다리를 붙여, 다리가 OpenAI 호환 주소처럼 보이게 합니다.
- **B**: 직접 만드는 확장과 같은 다리.

- **F는 기능은 가장 많지만 한국어가 막혀 있습니다.** `extension/gloss.mjs`의 프롬프트("Prefer the shortest natural Chinese word")와 응답 스키마(`pattern: HAN`), `validChinese()` 검사, `content.js`의 화면 글자('中文翻译' 등)를 모두 바꿔야 합니다.

- **혼합안의 추가 비용.** 기성 확장은 자기 캐시와 프롬프트를 쓰므로, 같은 단어를 Kiss와 자체 확장이 따로 AI에 물을 수 있습니다. 내 구독 한도가 이중으로 줄어듭니다. 캐시 공유가 되는지는 확인 못 했습니다.
- **참고용 코드.**
  - `rttr-extension`(MIT)은 실제 `<ruby>` 삽입 코드와 CEFR B2+ 선별 프롬프트가 있습니다. 별 0개에 커밋 1개라 참고용으로만 씁니다.
  - `AdaptiveTranslation`(MIT)은 수준 선택, 주석, 단어장 흐름이 Relingo와 가장 비슷합니다. 빌드 없는 바닐라 JS입니다.
  - Kiss Translator와 Read Frog는 GPL이라 읽기만 하고 복사하지 않습니다.
  - relyless(MPL-2.0)는 주석 일괄 요청 설계(`gloss.mjs`), 동적 페이지·코드 블록 건너뛰기(`content.js`), PDF 뷰어를 참고합니다. 파일을 통째로 가져오면 그 파일에 MPL 표기를 유지합니다(개인용·비배포라 의무는 가볍습니다).

## 5. 추천: B

**B를 추천합니다.** 지연 숫자와 한국어가 이유입니다.

- **단어 하나 왕복이 느립니다.** 상주 `claude`로도 3~4초, 콜드는 8초입니다. 처음 잡은 1.5초 기준을 못 맞춥니다. 그래서 "더블클릭 즉시 뜻"은 AI가 아니라 **캐시**가 해야 합니다.
- **한 단어씩 요청하면 주석이 불가능합니다.** 20개를 하나씩 물으면 약 70초(3.5초 × 20)인데, 일괄로 한 번에 물으면 2~5초입니다(생각 기능을 끈 상태). 주석은 처음부터 "화면에 보이는 단어를 모아 한 번에 묻고 캐시에 저장"하는 설계여야 합니다. A의 확장들에는 이 설계가 없습니다.
- **F(relyless)는 이 설계가 있지만 한국어로 바꾸는 비용이 큽니다.** 핵심 경로의 프롬프트·스키마·검사가 중국어 전제이고, 화면도 중국어입니다. 원본이 2주 만에 v0.7.1까지 올라온 빠른 프로젝트라 포크를 따라가기도 어렵습니다. 유지보수에 약하다는 점을 생각하면, 필요한 3기능만 가진 작은 코드가 오래 갑니다. 대신 relyless는 참고 코드로 씁니다.
- **캐시와 일괄 처리는 다리 한 곳에 있어야 합니다.** 더블클릭이 쓰는 캐시를 주석 페이지 로드가 미리 채워 주면, 더블클릭 대부분이 즉시 응답이 됩니다. B에서는 이 둘이 한 몸이지만 혼합에서는 갈라집니다.
- **B로 가도 A의 길이 막히지 않습니다.** 다리는 공통 부품입니다. B가 막히거나 지치면 다리에 OpenAI 호환 주소만 더해서 Kiss Translator로 1·3번을 곧바로 쓸 수 있습니다.

## 7. 에이전트가 정한 것

`결정 — 이유 — 틀리면 드는 비용` 순서입니다.

1. **확장↔다리 연결은 `http://127.0.0.1:47831` 로컬 서버(+토큰 헤더)로 합니다** — 단독 시험이 쉽고 상주 프로세스를 들고 있기 좋아서입니다. 네이티브 메시징은 Aside에서 실제 연결이 미확인이라 뒤로 미룹니다 — 틀리면 연결부 한 파일을 바꾸는 정도(기능 코드는 그대로).
2. **보안은 4겹으로 합니다.** `127.0.0.1`에만 바인딩하고, Host 검사를 하고, 임의 토큰 헤더를 요구하고, 토큰은 `/pair`가 내 확장 출처(`chrome-extension://<고정 ID>`) 하나에게만 자동으로 줍니다. 압축 해제 확장은 폴더 위치에 따라 ID가 바뀌므로 manifest에 `key`를 넣어 ID를 고정합니다 — 구독 한도를 쓰는 주소를 다른 웹페이지나 다른 확장이 칠 수 있어서입니다. 헤더가 붙으면 브라우저가 사전 확인을 강제하므로 남의 페이지가 막힙니다 — 틀리면 토큰을 손으로 한 번 붙여 넣는 수고입니다.
3. **기본 모델은 `claude` haiku 상주 프로세스입니다**(`--tools ""`, `--setting-sources ""`, `--settings '{"alwaysThinkingEnabled":false}'`, stream-json). `--bare`는 구독 로그인을 쓰지 않으므로 쓰지 않습니다 — 직접 잰 값이 가장 빠릅니다. codex 약 8초, agy 약 14초, `claude` 콜드 약 8초였습니다. 생각 끄기가 빠지면 첫 일괄 요청이 56~80초로 늘어납니다(2절). codex 구독이 최근 한도에 걸렸던 점도 반영했습니다 — 틀리면 엔진 교체 비용만 듭니다.
4. **프로세스는 요청 20건마다 재시작합니다** — 상주 세션은 대화가 쌓여 느려질 수 있어서입니다 — 틀리면 가끔 8초 지연이 한 번 생깁니다.
5. **단어 뜻 경로는 캐시 → AI 순서입니다. 첫 버전에는 사전이 없습니다** — 보안 용어(mitigate, payload, sanitize, obfuscate)는 위키 기반 영한 사전에 없고 exploit은 뜻이 틀렸습니다. 어차피 AI가 주력입니다 — 틀리면 나중에 사전 JSON을 앞단에 끼웁니다.
6. **어려운 단어 판정은 CEFR-J 1.5(A1~B2) + Octanove C1/C2로 하고, 기본은 B2 이상에 주석을 붙입니다.** 표제어는 `wink-lemmatizer`로 구합니다. 목록에 없는 단어도 후보로 보냅니다. payload·mitigate·sanitize처럼 보안 문서의 흔한 어려운 단어가 CEFR-J에 없기 때문입니다. AI가 "고유명사·코드·이미 쉬움"이면 빈 값으로 돌려 거릅니다 — 라이선스가 명확하고(합쳐서 약 280KB, CEFR-J는 인용 조건, Octanove는 CC BY-SA 4.0) 단계 설정이 쉽습니다 — 틀리면 기준값 하나를 바꿉니다. 빈 값도 캐시에 저장해서 같은 단어를 다시 묻지 않습니다.
7. **캐시는 다리 쪽 파일 `~/dev/readgloss/data/cache.json`에 둡니다** — 확장은 상태가 없고 Aside와 Chrome이 같은 캐시를 씁니다 — 파일이 깨지면 지우고 다시 받으면 됩니다.
8. **캐시 키는 소문자 표제어입니다.** 문맥이 다른 뜻은 말풍선의 "이 문장으로 다시 묻기" 버튼으로 덮어씁니다 — 다의어(exploit 등) 대응이 필요해서입니다 — 틀리면 엉뚱한 뜻이 남지만 버튼으로 고칩니다.
9. **주석은 "화면에 보이는 문단 + 한 화면 앞"만 일괄 요청합니다.** 한 번에 최대 20단어, 스크롤이 멈추면 새로 보이는 문단을 이어서 처리합니다 — 측정한 호출 크기가 20단어였고 한도 낭비를 막습니다 — 틀리면 스크롤 직후 주석이 몇 초 늦게 붙습니다.
10. **주석 자동 실행은 기본 꺼짐입니다.** 툴바 버튼으로 켜거나 "자동으로 켤 사이트" 목록에 넣습니다. 더블클릭과 문단 번역은 늘 켜져 있습니다 — 구독 한도를 지키기 위해서입니다 — 틀리면 클릭 한 번이 늘어납니다.
11. **프롬프트는 "정보보안 문서 맥락의 짧은 한국어 뜻(8자 안팎)"으로 하고, JSON만 출력하게 합니다.** 굳어진 보안 용어(취약점, 완화, 인젝션)는 그대로 쓰고 코드펜스는 파서가 벗깁니다 — 측정에서 sanitization=정제, primitive=기본 요소처럼 어색한 뜻이 나왔고 코드펜스로 감싼 출력이 나왔습니다 — 틀리면 프롬프트 수정입니다.
12. **폴더는 `~/dev/readgloss/`입니다.** 구성은 `extension/`(확장), `bridge/`(다리), `scripts/`(단어 목록 빌드), `data/`(캐시, git 제외)입니다. 원격 없는 로컬 git 저장소로 두고 push하지 않습니다 — 이름과 위치는 바꾸기 쉽습니다.
13. **언어와 빌드: 빌드 도구 없는 순수 JS(ES 모듈)입니다.** 다리는 Node 20 이상, 의존 패키지는 `wink-lemmatizer` 하나, 테스트는 내장 `node --test`입니다 — 가장 작게 시작하라는 요구와 손볼 곳이 적은 구조 때문입니다 — 틀리면 나중에 번들러를 얹으면 됩니다.
14. **라이선스: 개인용이고 배포하지 않습니다.** 참고 코드는 MIT(`rttr`, `AdaptiveTranslation`)와 MPL-2.0(relyless, 가져온 파일에 표기 유지)만 출처를 적고 가져오며, GPL 코드는 복사하지 않습니다 — 약관과 라이선스 위험을 줄입니다 — 틀리면 해당 부분을 다시 씁니다.

## 8. 완료 조건

**수용 기준**(전부 통과해야 완료입니다)
- 사용자가 고른 실제 영어 보안 글 1편(예: PortSwigger나 Project Zero 글, 바꿔도 됩니다)에서 다음을 확인합니다.
  1. 모르는 단어를 더블클릭하면 2절의 시간 안에 한국어 뜻이 나옵니다.
  2. 주석을 켜면 B2 이상 단어 위에 작은 한국어 뜻이 붙고, 코드 블록은 그대로입니다.
  3. 문단에서 단축키를 누르면 아래에 번역이 붙고, 다시 누르면 사라집니다.
- 같은 페이지를 새로 열면 AI 호출이 0번입니다(다리의 요청 통계로 확인).
- 다리를 끈 상태에서 확장이 "다리가 꺼져 있어요: 실행 방법"을 보여 주고 페이지는 깨지지 않습니다.

**자동 테스트**(작은 것 하나씩, `node --test`)
- 난이도 판정: `the`는 안 붙고, `mitigated`는 `mitigate`로 바뀌어 붙습니다.
- 캐시: 같은 단어를 두 번 물으면 두 번째는 가짜 AI 호출이 0번입니다.
- 파서: 코드펜스로 감싼 JSON도 읽고, 깨진 출력은 에러로 처리합니다.
- 인증: 토큰이 없으면 401, 남의 Origin이면 403이 나옵니다.
- 단어 쪼개기 순수 함수: 문장과 뜻 사전을 넣으면 조각 목록이 나옵니다. 브라우저 없이 시험합니다.

**수동 확인 절차**
1. 다리를 실행합니다.
2. Aside에 확장을 올립니다.
3. 보안 글 1편을 열어 2~3번 과정을 눈으로 확인합니다.
4. 다리를 껐다 켜서 캐시가 남는지 봅니다.

## 9. 4줄 요약

- **문제**: 영어 보안 문서를 읽을 때 모르는 단어를 찾느라 흐름이 끊기고, Relingo는 유료이며 구독 CLI로는 못 씁니다.
- **비용**: 돈은 0원입니다. 만드는 데 약 5세션(티켓 5개)이 듭니다. 유지보수는 내 코드 1개와 다리 1개입니다. 구독 한도는 캐시, 일괄 요청, 켠 사이트에서만 자동 실행으로 줄입니다.
- **기대 결과**: 더블클릭 뜻, 단어 위 자동 주석, 문단 번역을 구독만으로 쓰고, 한 번 본 단어는 다시 AI를 부르지 않습니다.
- **검증 방법**: 8절의 실제 보안 글 1편 수용 기준과 `node --test`를 통과하고, 같은 페이지 재방문 시 AI 호출이 0번인지 확인합니다.

## 11. 티켓 초안

한 티켓은 한 세션 분량이고, 각각 앞에서 뒤까지 닿는 얇은 조각입니다.

**T1. 뼈대: 더블클릭 → 한국어 뜻**
- 범위: `~/dev/readgloss/` 생성. 다리(`/ping`, `/pair`, `/lookup`, 상주 `claude` 호출(생각 끄기 설정 포함), 캐시 파일). 확장 뼈대(manifest와 고정 `key`, service worker, 더블클릭 말풍선). `scripts/bench.mjs`(새 프로세스 첫 호출과 이어지는 호출을 따로 잽니다).
- 완료 조건: Aside에 확장이 올라갑니다. 더블클릭하면 6초 안에 뜻이 나오고, 두 번째는 0.3초 안입니다. 인증 테스트와 캐시 테스트가 통과합니다. 다리를 끈 상태의 안내 문구가 나옵니다.
- 선행: 없음. 시간 상자: 한 세션.

**T2. 문단 번역**
- 범위: 다리 `/translate`. 문단을 찾는 코드. Alt+T 토글. 문단 해시 키 캐시.
- 완료 조건: 100단어 문단이 6초 안에, 재호출은 0.5초 안에 나옵니다. 코드 블록은 문단 대상에서 제외합니다.
- 선행: T1.

**T3. 어려운 단어 판정과 일괄 주석 요청**
- 범위: `scripts/build-wordlists.mjs`(CEFR-J 1.5와 Octanove C1/C2를 JSON으로 변환). 다리 `/annotate`(표제어 정규화, 기준 B2, 캐시 확인, 20단어씩 묶어 요청, 빈 값도 캐시에 저장). `scripts/sample-gloss.mjs`.
- 완료 조건: 난이도 판정, 파서, 캐시 단위 테스트가 통과합니다. 표본 20단어의 뜻을 사용자가 검수할 수 있게 출력합니다.
- 선행: T1.

**T4. ruby 주석 화면 그리기**
- 범위: 텍스트 노드를 쪼개 `<ruby>`로 감싸는 순수 함수와 테스트. 보이는 문단 + 한 화면 앞만 요청. 스크롤 멈춤 뒤 이어서 요청. `pre`, `code`, 입력창은 건너뜁니다. 주석 글자는 선택·복사에서 제외합니다.
- 완료 조건: 실제 보안 글에서 2번 기능의 성공 판정을 통과합니다. 재방문에서 AI 호출이 0번입니다.
- 선행: T3(그리고 T1의 확장 뼈대).

**T5. 상시 실행과 켜기/끄기**
- 범위: 툴바 버튼 켜기/끄기. "자동으로 켤 사이트" 목록. 상태 표시(다리 꺼짐, 오늘 요청 수). 다리 상시 실행(launchd 등록 파일 1개). 10분 놀면 `claude` 종료, 20건마다 재시작.
- 완료 조건: 로그인 뒤 다리가 자동으로 떠 있습니다. 8절 수용 기준 전체를 통과합니다.
- 선행: T4.

**첫 걸음(사용자가 직접 할 것, 5분)**: Aside에서 `chrome://extensions`를 열어 "개발자 모드" 토글이 있고 켜지는지 한 번만 봐 주세요. 켜지면 T1을 바로 시작합니다. 안 켜지면 Chrome으로 먼저 가고, 나머지는 같습니다.
